# 主题成分的当前观测与追溯

[English](THEMES.md) · [个人使用教程](USER_GUIDE_CN.md) · [实际待办](backlog.json)

## 能力边界

主题资料使用东方财富公开概念目录和成分接口，与 AKShare 概念板块接口同源。读取的是供应商当前返回的成分，不是交易所认证的主题分类，也不是历史成员数据库。网络可访问不等于授权长期可用或服务等级保证。

应用保存每次成功观测，包含板块代码、精确名称、全部原始分页响应、请求参数、逐页接收时刻、清单哈希及支持证券。目录及成员必须完整遍历，供应商总数稳定，身份不重复；缺页、数量不符、名称冲突和无效字段均拒绝发布完整快照。多个 HTTP 页面不是供应商原子快照，即使这些检查通过，也不能证明取数期间成分从未发生等数量替换。

逐页响应保存的是 HTTP 客户端解码后的响应字节，不包含 TLS 或压缩传输的原始网络帧。清单绑定原始文件哈希、请求和接收时间；查询重新校验清单、原始页以及全部数据库成员，再返回分页。资料只追加，不用今天名单覆盖旧版本。

## 时间与研究使用

`published_at` 未知；`known_at` 使用完整响应收集完成后的接收时刻。按过去时点查询只能得到当时已经归档的版本，首次采集以前返回未观测。不能指定历史日期把当前名单回填为历史，也不能由调用者传入伪造的过去接收时间。

结果区分供应商成员总数、支持的沪深 A 股数量及排除数量；不把北京证券交易所或其他不支持的标的无声算入可交易范围。成员身份只代表主题分类，不证明当天非 ST、未停牌、价格带、流动性或交易许可。

“新能源”等偏好可能对应多个细分概念。当前要求显式的板块代码或精确供应商名称（两者同时给出时必须一致），不自动合并光伏、新能源车等概念，也不会改变用户已保存的研究偏好。页面已有只读主题归档展示；板块映射版本、定时采集和后续研究推荐仍需单独接入。

## 运行与安全

采集是有界的独立任务，不加入行情撮合进程。网络只访问固定 HTTPS 端点，不接受任意 URL，不跟随重定向、不自动重试；请求数量、响应大小、分页数和任务总时长均有上限。失败保留已发布的旧观测，但旧观测不能冒充新鲜数据。

PostgreSQL 是观测索引与成员的持久化主存储，原始文件在证据卷中；现有备份覆盖 `qd_ashare_*` 表及证据目录。持续检查验证最近板块观测，损坏时报告故障；一次成功采集不会将历史主题待办标为完成。

该模块不持有模型或券商密钥，不写入模拟委托、不审核每日证券规则、不批准策略。实盘与 AI 自动晋级继续禁止。

## 运维入口

在后端环境完成迁移后，按精确名称采集一个板块：

```bash
python -m app.ashare.themes ingest --name 人工智能 --evidence-dir /app/data/evidence/themes --timeout 60
```

命令需要现有 `ASHARE_DATABASE_URL` 或 `DATABASE_URL`；不要把连接密码粘贴到终端输出或聊天。实际部署应在现有模拟容器中执行，宿主环境不需要开放数据库端口。该命令不会向账户添加自选或下单。

若需查看完整概念目录，可单独运行 `python -m app.ashare.themes catalog --evidence-dir /app/data/evidence/themes --timeout 30`。目录命令只产生检查用的原始归档，不写入持久化主题成员表；生产主题以成功的 `ingest` 记录为准。无需为了执行 `ingest` 先额外跑目录命令。

取得供应商实际板块代码后，运行 `python -m app.ashare.themes snapshot --board-code BK实际代码 --limit 100 --offset 0`；`BK实际代码` 是占位符，必须替换为回执中的实际代码。可加 `--known-at` 和带时区的 ISO 时间查询当时已知的版本，不能用该参数写入或回填历史。
