# 官方页面里的 A 股模拟交易

[English](WEB_WORKSPACE.md)

日常长期运行请使用[独立持久化部署](DEPLOYMENT_CN.md)，配合[健康检查与日报](OPERATIONS_CN.md)。下方命令仅供本地开发；跨日受控验证见[验证指南](MULTIDAY_VALIDATION_CN.md)。

本扩展在官方 Vue 前端的菜单中加入 **A 股模拟**（`/#/ashare-paper`），复用官方登录、JWT、角色和语言系统。页面提供盘中报价、时间与新鲜度、虚拟资金/持仓、模拟买卖、撤单、委托/成交记录、当日规则审核、关注列表，以及飞书配置引导。HTTP 接口只处理鉴权、校验和持久化，独立 worker 采集行情并撮合。

## 部署到现有 Fork

后端与独立前端均需更新，官方预编译前端镜像不会自动包含这个新增页面。前端扩展的固定版本、许可和构建方式见 [前端说明](../../frontend_extensions/ashare-paper/README_CN.md)。前端源码来自独立仓库，采用独立许可；此 Fork 仅保存新增页面、小范围补丁和可重复构建脚本。

在已有官方后端环境中安装 `backend_api_python/requirements-ashare.txt`，保留原有后端完整依赖。配置现有 `DATABASE_URL` 和稳定的 `SECRET_KEY`；也可通过 `ASHARE_DATABASE_URL` 指定单独的模拟数据库。两者使用不同地址时，认证数据库与模拟数据库都必须可用。新表均为 `qd_ashare_*`，不复用实盘账户余额。

在 `backend_api_python` 目录执行：

```bash
# 首次部署或升级，显式运行迁移
python -m app.commands.migrate

# 继续使用官方后端启动方式；本地开发可使用以下环境
export QD_PROCESS_ROLE=api
export SKIP_STARTUP_HOOKS=1
export PYTHON_API_HOST=127.0.0.1
export PYTHON_API_PORT=5017
python run.py
```

另一个进程使用相同环境启动模拟 worker：

```bash
python -m app.ashare.managed_worker --cycles 0
```

在仓库根目录准备官方前端：

```bash
python scripts/frontend/prepare_ashare_frontend.py ../work/quantdinger-frontend --build
cd ../work/quantdinger-frontend
VITE_DEV_PROXY_TARGET=http://127.0.0.1:5017 pnpm dev --host 127.0.0.1 --port 5177
```

需要 Node 与 pnpm（采用官方前端要求及锁文件）。Windows 使用 PowerShell 的 `$env:变量名` 设置环境变量。上述 localhost 命令用于开发/验收；长期部署沿用官方反向代理和生产 WSGI 启动方式，并由 systemd 或容器分别管理 API 和 worker，配置失败重启。不要把开发服务器直接公开到互联网。

## 页面操作

1. 登录官方页面，通过菜单进入 **A 股模拟**。新账户选择初始虚拟资金；再次初始化不会重置资金。
2. worker 启动后显示真实行情；关注列表可以修改证券和采样间隔。仍有持仓或挂单的证券不能直接移除。
3. 点击 **审核规则**，检查当日证券状态、涨跌停价并填写来源依据。审核保存操作者、时间、报价原始哈希和审计记录。系统不会替人勾选审核，也不会自动顺延到下一天。
4. 填入买卖方向、整手数量和限价，核对确认框后提交。买单先冻结资金，后续新鲜报价才可能成交；当日买入股份不能卖出。撤单释放剩余预留。所有操作只影响本用户的虚拟账户，viewer 不能写入。

只支持已审核、非 ST 主板/创业板股票的 100 股整手连续竞价模拟。集合竞价、科创板、北交所、零股和公司行动仍未实现。网页快照与盘口量是模拟输入，不保证等同交易所逐笔数据或真实排队成交。

## 连续运行和每日规则

worker 自动识别交易日、开盘前、午休、收盘集合竞价和收盘；非连续竞价不撮合。当日证券规则失效后显示等待审核，采集行情本身不构成批准。当前固定 XSHG 日历覆盖到 **2026-12-31**，超过已知范围禁止交易，需要先更新并验证日历。

昨日未完成的当日单在新日期循环中自动过期并释放预留，不再依赖新鲜行情。页面配置和审核变化在运行时重新读取。同一账户/worker 的数据库锁防止重复运行；数据库断线按 1、2、4…最多 30 秒重连，单账户行情失败不影响其他账户。当前为顺序轮询，尚未验收大量账户同时运行。

API 将认证数据库故障返回为 503，避免把基础设施故障当作无效登录；业务仍拒绝执行，恢复后原有效会话继续工作。无效签名和撤销的会话仍返回 401。页面用本地时钟持续计算报价年龄，即使轮询失败也不会把旧报价一直显示为新鲜。

## 飞书运行引导

打开 **飞书推送** 页签，按页面步骤创建群自定义机器人，填写 Webhook 和可选签名密钥，保存后主动点击 **发送测试消息**。个人账户需具备群机器人权限；不配置也能正常模拟。

地址/密钥按账户加密入库，页面只返回配置状态，不回显秘密；换机器人需重新填写。**停用推送** 会清除本账户配置。`SECRET_KEY` 必须至少 32 字节且稳定保存，变更后旧加密配置无法读取，需要重新配置。worker 仅在成交或运行状态改变时通知，不接收飞书交易指令，不自动重试可能已经送达的消息。当前没有真实 Webhook，因此真实送达仍待用户点击测试验证。

## 验收与限制

见 [页面验收报告](WEB_ACCEPTANCE_CN.md) 和 [接口契约](paper-web-openapi.json)。持续禁止真实券商和 AI 自动晋级；新增页面不授予 Agent 写权限。界面接入完成不表示已把官方任意 Strategy V2 策略部署自动接入新账本，也不表示多交易日连续运行已自然观察完成。

## 本地账号修改密码

在个人中心的“修改密码”页，默认选择“当前密码”：填写当前登录密码、新密码和确认密码，无须配置邮件。新密码至少 8 位，含大小写字母和数字；修改成功后所有旧会话失效，请重新登录。连续输错会受到限流。

“邮箱验证码”是另一种验证方式，须先配置服务器 SMTP 并绑定可接收邮件的账号邮箱；验证码不是登录密码。尚未设置密码的账号必须完成邮箱验证。邮件未配置时会明确提示，不会生成无法送达的验证码。不要把账号密码、邮箱验证码或 Webhook 发到聊天或提交到仓库。

## 历史股票池与批量人工审核

“A 股模拟”下方新增“历史股票池”页签，按 `YYYY-MM-DD` 查询已经采集的日期，每页 100 条。不把当前成分回填历史；未采集日期显示不可用。日期股票池覆盖范围、来源与获取时间以存储记录为准；BaoStock 日终状态不是交易所认证数据，也不证明当日上午已知。

行情区右侧“批量审核关注证券”一次整理关注列表中各证券的当日涨跌停报价和逐日状态证据。每只证券仍须人工核对并勾选“今日未停牌、非 ST 且涨跌停价已核实”，可为所选证券填写一次共用的、带日期的审核来源，再统一保存。所有行先校验，再在同一事务保存；任一行无效，全批拒绝。查看资料不会写入审核结论。旧日期不复用，供应商没有当日状态时保持“未知，需人工核实”。缺失/损坏原始证据、当日报价缺失、证券名称带 ST/退或当日来源显示 ST/停牌时禁止批准。

页面顶部新增“飞书推送”快捷入口，会展开并滚动到配置区域。添加飞书自定义机器人须使用飞书电脑桌面客户端，手机端没有该添加入口。

## 研究方向偏好

在“关注列表”选择人工智能、机器人、新能源、半导体，或填写其他研究方向，也可勾选“研究时考虑时事热点推荐”，然后保存。偏好按登录账户隔离保存。目前只记录选择，尚未执行资讯抓取、主题成分映射、自动选股或策略启用。后续 AI 研究及优化结果需经人工审批后，才可进入获批策略的自动模拟执行；当前面板不代表该完整流程已实现。
