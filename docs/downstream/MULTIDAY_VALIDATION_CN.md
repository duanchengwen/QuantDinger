# 连续多交易日模拟验收

[English](MULTIDAY_VALIDATION.md)

## 验收性质

此命令使用**合成行情、受控时间和明确标记的测试操作者审核**，在真实 PostgreSQL 中运行实际 ManagedWorker、PaperBroker、费用和日报逻辑。它验证跨日行为，不表示系统已经自然连续观察多个真实交易日，也不代表策略收益或行情源质量得到验证。

不会读取券商凭据，不会连接真实券商，不会调用模型，不会发送飞书消息。运行时创建随机独立数据库 schema 和独立测试账户；无论通过还是失败，只清理本次创建的 schema，不接受已有账户/schema 参数。请使用专用可丢弃测试数据库。测试需要创建/删除 schema 的权限，以及终止本测试自己的 PostgreSQL 会话的权限；建议使用 PostgreSQL 18。

## 执行

在后端目录安装已有测试依赖，设置专用测试连接（不要把实际密码提交到仓库）：

```bash
cd backend_api_python
export TEST_ASHARE_DATABASE_URL='postgresql://test_user:TEST_PASSWORD@127.0.0.1:5432/test_database'
python -m app.ashare.multiday_validation --output reports/acceptance/multiday.json
python -m pytest tests/ashare/test_multiday_validation.py -q
```

默认只读取 `TEST_ASHARE_DATABASE_URL`，不会自动回退到应用数据库配置。`--database-env` 可以显式指定另一个环境变量名称。成功退出码为 0，失败为 1；缺少必要参数/连接配置为 2。JSON 保存结果、每个断言、日报、订单、成交、最终资金与持仓、Python/PostgreSQL/日历版本和相关代码 SHA-256。同目录下保存明确标记为合成的输入 JSON，每笔成交的证据哈希可核对原始文件。

验证成功后临时数据库已删除，但验收 JSON 和合成证据目录保留。退出失败时 JSON 给出失败断言或经过脱敏的错误类型；连接字符串不写入报告或日志。

## 覆盖场景

连续交易日序列为 2026-09-28、09-29、09-30、10-08、10-09、10-12、10-13，中间加入 10-01 国庆休市、10-03 和 10-10 周末检查，日期由固定版本 XSHG 日历再次校验。

每个交易日验证：

- 开盘前不撮合；旧审核不能顺延，操作者在测试中明确提交新审核后才允许撮合。
- 上一个交易日买入的股份可卖出；当日新买股份仍被 T+1 拒绝卖出。
- 300 股买单在 100 股对手盘下仅成交 100 股，剩余资金正确预留；撤单释放余款。
- 过期和未来时间的报价不成交；重复和乱序报价不重复消耗盘口。
- 强制终止**本测试自己的**数据库会话后重连，同一委托重试和行情重放保持幂等。
- 午休停止、下午恢复、收盘集合竞价不撮合、15:00 当日单过期并释放冻结资金。
- 收盘后再次重连及循环不会重复生成日报；日报资金和持仓对账正确。
- 每个关键阶段核对现金守恒、持仓守恒、冻结资金守恒、可用资金非负和无额外策略委托。

## 本轮结果

2026-11-17 在 PostgreSQL 18 上完成 7 个交易日、294 个场景断言、14 次连接重建（其中 7 次强制终止测试会话）、13 笔虚拟成交及 7 份唯一日报。初始资金 100,000 元，最终现金 98,925.87 元，剩余 100 股，冻结资金为零。金额仅用于固定测试输入的确定性校验，不是收益评估。

Python 3.11 和 Python 3.12 均通过；上游日历/pandas 弃用警告保留。自动测试另检查失败报告不泄露连接信息，以及失败时清理独立 schema。
