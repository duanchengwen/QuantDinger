# A 股模拟部署的只读持续检查

[English](MONITORING.md) · [使用教程](USER_GUIDE_CN.md) · [运行记录](OPERATIONS_CN.md)

在仓库根目录执行；将下面路径替换为真实部署路径：

```bash
python scripts/ops/paper_monitor.py \
  --state-dir /srv/quantdinger-paper/state \
  --backup-root /srv/quantdinger-paper/backups \
  --backlog docs/downstream/backlog.json \
  --output /srv/quantdinger-paper/monitor/latest.json \
  --quiet-unchanged /srv/quantdinger-paper/monitor/baseline.json
```

工具不下单、不审核、不发送飞书消息、不重启服务。它经现有 API 容器执行一个有超时的 PostgreSQL **只读、可重复读事务**，不新增数据库端口，也不把密码传到命令行。报告隐藏租户/账户名称、余额、持仓数量和机器人地址；使用账户哈希引用，仍应把运行报告保存在私有目录。输出和静默基线拒绝写入 Git 仓库，权限为 0600。

## 检查内容

- API、worker、数据库、网页四个容器是否正在运行且健康，worker 心跳是否在 120 秒内。
- 当前账本资金、股份、每单成交额/费用和预留是否与全部成交聚合一致；使用同一只读快照，不截断交易历史。
- 连续竞价期间的源时间、接收时间和原始哈希是否可用；源/接收时间超过 15 秒或来自未来会告警。休市的旧行情不作为盘中故障，但仍保留源时间。
- 实际读取当前报价对应的原始证据文件并核对 SHA256，休市也检查；拒绝 `/app/data` 之外的路径和超过 16 MiB 的文件。最近 10 份证券状态接收记录若已安装则同样核对文件、记录日期/证券数/状态数，并检查接收时间没有来自未来。`known_at` 采用实际接收时刻，不冒充原始发布时间。旧部署尚无状态表时显示待接入，监测仍能运行。
- 数据卷剩余空间不足 100 MiB、备份所在文件系统不足 500 MiB 时告警。这只是当前容量阈值检查，不能预测下一份备份是否能放下。
- 当前环境的实盘、Agent 实盘、AI 自动晋级开关是否保持 false。这是部署配置检查，不能代替源码安全测试。
- 备份目录内最近一份有时间清单的备份是否通过全部文件 SHA256 和归档路径安全检查，是否在 30 小时内。最近备份坏了不会悄悄改用旧备份。这里只做读取校验，不自动恢复、不删除备份。
- 最近 90 个有记录日期中的真实时钟、受控时间采样与日报。只有日历确认的交易日且存在真实时钟采样才计入 `natural_sample_days`，周末和未知日历不计。该列表是所有账户的日期并集，不表示每个账户都已完整观测这些日期。

退出码 0 代表本次检查没有运行告警；1 代表报告中存在 `issues`；2 代表监测本身失败，错误只输出类型而不回显 Docker stderr 或连接秘密。即使没有运行告警，`pending_acceptance` 仍可能有待办，不能把退出码 0 解读为产品已全部验收。

`--quiet-unchanged` 在运行状态、告警、待验收项、自然采样日期或日报数量发生变化时输出；仅计数、报价时间推进或时钟变化保持静默。即使静默，失败退出码仍保留。`--output` 每次更新完整 JSON，便于定时检查读取。

`--backlog` 可读取仓库内维护的 `{items:[{id,status,acceptance}]}` 清单，报告条目状态、验收依据和未完成 ID。`accepted`/`complete` 作为已验收声明，`prohibited` 作为禁止范围，其余状态均继续保留待办；监测不会自己修改清单或仅凭健康状态批准条目。

## 自然多日验收边界

默认目标为至少 5 个自然交易日的采样日期，可用 `--target-days` 调整。此阈值仅表示观测进度：首日从中午启动、每日报告只有一次采样、多个日期只有离散心跳，都不能证明完整开市时段持续在线。现有聚合记录不包含完整逐次轮询间隔，工具明确保留 `intraday_gap_and_full_session_coverage_not_proven`，并持续返回 `natural_multiday_complete=false`，需要结合轮询记录和运行日志另行验收。受控回放次数不会计为真实运行天数。

监测不会批准每日规则，不会把公司行动、历史时点数据、资讯、行业推荐、策略研究、Windows 或 CI 等其他待办自动标成完成。后续行业资讯、推荐与模拟策略更新仍需独立验收，策略变更由人工批准。`completed_backlog=false` 是对当前边界的明确说明。功能验收、来源可靠性与自然运行结果需要分别留下证据。

可由本聊天的周期检查调用该命令。只有新的故障、恢复、验收进展或确实需要用户处理时提示；状态未变时保持安静。主机休眠、关机或调度器未运行时无法持续观测，也不能承诺零中断。工具本身不会创建系统定时器。

主题快照部署后，监测会校验最多十个板块的最新观测：清单、全部原始分页和数据库成员重新比对，知识时间不能处于未来。主题成员校验通过不代表历史覆盖完整，也不授权交易。

主题定时采集安装后，监测读取 `quantdinger-themes-<project>.service` 的退出状态，并仅从私有状态文件摘取经过校验的状态、配置版本、窗口日期和时间。systemd 成功不等于实际采集完成：盘前跳过或未执行保留 `theme_sync_first_window_not_completed`；部分失败、损坏状态、未来时间和超过 30 小时的完成时间会报告问题。状态文件不替代数据库与原始主题证据校验；监测不触发采集或重试。
