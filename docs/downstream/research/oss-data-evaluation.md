# 数据与资讯开源复用评估

核查日期：2026-11-17。范围：A 股历史数据、盘中网页行情、官方公告、证券主数据。按用户最新要求暂停扩大自研，先核查现有方案；本文件不代表已经切换依赖或部署生产服务。

## 建议

保留并优先复用 AKShare 的历史数据和公告目录能力；盘中网页行情优先验证 easyquotation 的现成解析器，再用很薄的一层补上来源存证、时区、超时和过期拦截。BaoStock 应先升级到经验证的官方新版，再判断服务故障。需要明确交易所授权与服务质量的实时数据，应经独立数据适配器接入授权服务；免费网页快照不应被描述为有确定延迟保证的交易所 tick。

这些项目解决了数据接入的大量重复工作，但不能代替本系统的账户对账、点时历史、证据归档、时效校验或策略审批。这是基于源码和本机实测的工程判断，不是按星标数评定质量。

## 源码核查发现

AKShare 的官方公告函数已经处理股票到机构 ID 的映射、分页及公告时间转换。因此无需另造一套通用公告搜索框架。但高层结果会选择少量列并生成详情链接，原始列表 JSON、附件字节、采集时刻与哈希仍需在传输边界补留。源码里的时间转换最终去掉时区，消费端必须明确恢复上海时区，不能按本机时区猜。[公告源码](https://github.com/akfamily/akshare/blob/main/akshare/stock/finance/stock_disclosure_cninfo.py)

easyquotation 的腾讯解析器已提供报价时间、五档价量、累计成交量和上下限。源码将相应量字段从手换成股，与本次真实样本一致；但时间对象没有时区，默认地址为 HTTP。[腾讯解析器](https://github.com/shidenggui/easyquotation/blob/master/easyquotation/tencent.py)

本次读取的 easyquotation 提交为 `7778c1b9f93afb2ce2cf431de393fe690d4ec07c`；AKShare HEAD 查询结果为 `25acdfac7ddf3a0721a0ebdcc6a1d7ef3e76abc9`。正式复用应固定验收版本；仓库 push 时间和 HEAD commit 时间不是同一概念。

其基类网络请求没有显式 timeout，并以线程池请求多个批次。直接把它放在模拟账户的主循环会让供应商故障影响账户时钟；适合保留解析器并包装有期限的 HTTPS 下载，避免对全市场高频轮询。[传输基类](https://github.com/shidenggui/easyquotation/blob/master/easyquotation/basequotation.py)

AKShare 官方发布记录也把接口变化和东财 push2 请求限速列为维护事项。这支持“固定版本、限频、明确失败、保留源证据”的方案，而不能支持“装上开源库就保证实时可靠”的结论。[官方发布记录](https://github.com/akfamily/akshare/releases)

## BaoStock 旧版问题的更正

之前 V0.2 的 `READ_TIMEOUT` 是 **0.8.9 客户端及其端点的实际失败**，不应扩展为“当前 BaoStock 官方服务不可用”。本次核查官方 0.9.4 wheel 后确认：公共主机已由 `www.baostock.com` 改为 `public-api.baostock.com`，登录连接方法增加 `api_key` 参数，公开匿名模式默认 `0`。这些均来自官方发布包，不是自行寻找替代服务地址。

在独立目录加载官方 0.9.4，不改主环境依赖、不提供任何密钥，本机实测成功：

| 调用 | 结果 |
| --- | --- |
| 官方匿名登录 | 3.572 秒成功 |
| sz.000001，2025-01-06 至 2025-01-10，不复权日线 | 5 行，error_code=0 |
| query_all_stock，2025-01-06 | 6701 行，error_code=0；包含指数等非股票，不能全部当 A 股股票 |
| 交易日历，同一区间 | 5 行，error_code=0 |
| 完整探针含登出 | 30.891 秒，退出码 0 |

记录在 `runtime/v03-data-probes/bao094/`。新库的接收循环仍需要期限与 EOF 保护；最小修复是兼容新增公开参数，继续使用**当前 SDK 内的官方公共端点常量**，保留原有读写/大小/EOF 门槛。不得将旧版端点硬编码到新版，也不因出现 API-key 参数就擅自进入付费模式。

后续带保护层的测试取到 2020-01-06 的 4575 行，但同会话下一次较大请求触发 10 秒总响应期限。成功与失败均保留：这说明升级解决旧端点不兼容，同时完整历史池仍需合适的有界期限、限频和故障恢复，不能承诺永不超时。

随后分别使用独立公共会话和 25 秒响应期限，2025-01-06 与 2026-11-16 成功取得 6701、7450 行，含登录/登出耗时 21.658、27.731 秒。三期都保留请求日期、实际采集时间和完整原始行，位置 `runtime/v03-data-probes/bao094-dated/`。沪深股票前缀过滤后只是候选集，分别 3764、5124、5224 条，尚不是经过类型验证的全市场历史库。

`sz.000005` 在 2020 日期池存在、2025/2026 不存在；另用 `query_stock_basic` 查得证券类型 1、状态 0、退市日 2024-04-26，形成真实退市样本的独立字段核验。特别注意：旧日期池里的部分 `code_name` 已带后来退市名称，因此不能用名称重建当年的 ST 状态或当时已知名称。这是实采记录显示的限制。

建议根项目在完整回归后将 BaoStock 锁到 `0.9.4`，再做来源交叉核验；主环境依赖由协调者统一调整。软件更新解决了本次可复现的接入问题，并不等于完整历史池和所有证券状态已经验收。

## 未通过项与下一步决策

当前免费网页链路已实采两只股票，盘口时间比接收时刻落后约 2.8 / 4.8 秒，仅说明当次可用。当前交易所清单单次分别取到 SZSE 2905 行、SSE 主板 1700 行；再次组合采集发生读取超时，未发布完整组合包。数据服务波动是真实存在的，不能只报告一次成功。

尚未验证：easyquotation 安装后的同样本兼容与长期运行；授权实时服务及其延迟保证；全部板块与历史退市证券的完整性；历史证券状态的自动逐字段取证；公司行为精确净税处理。推荐在复用方案确定后先做小范围双源实测、限频和故障恢复，再扩大股票池。禁止为跑通而把未知状态改为正常。
