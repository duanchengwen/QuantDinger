# 公司公告资讯源：CNinfo 首个有界接入

[English](NEWS_SOURCES.md)

研究日期：2026-11-18。仅使用来源官方网站及其公开响应核实；未访问生产数据库、模型或飞书。此次探测不构成生产持久回执，不证明每天持续可用。

## 来源选择与真实探测

选择[巨潮资讯网](https://www.cninfo.com.cn/)的[公开公告查询端点](https://www.cninfo.com.cn/new/hisAnnouncement/query)，读取公司公告标题、发行人代码/名称、供应商公告时间和官方 PDF 路径。该 POST 端点在本次不带账户或 API key 的请求中返回 HTTP 200；接口没有公开稳定性契约，公开可访问不等于长期服务保证或再分发许可。本实现供本机证据研究使用，没有绕过登录、付费或访问限制。

一次“人工智能”查询返回 30 条记录、提供商总数 252；第一条是招商公路投资设立人工智能产业基金的关联交易公告，供应商时间对应 2026-10-30，不能把这次收到的旧公告称为今天的新闻。[官方原始 PDF](https://static.cninfo.com.cn/finalpage/2026-10-30/1225642382.PDF) 的独立请求返回 HTTP 200、136937 字节，SHA-256 为 `e2494fc48dd8b52f716c4b69c0066e6c22095e667336182f26c2d786464dfde4`。探测只确认 PDF 字节可读取，没有提取或验证其全文。

第三次也是最后一次 CNinfo 探测使用“机器人”、每页 5 条，返回 HTTP 200、3832 字节、5 条记录，提供商总数 14229。五条标题均未出现“机器人”。因此**供应商全文搜索命中不能直接证明标题主题关联**。实现额外对标题做明确关键词筛选，允许零命中；不会因供应商返回了结果就声称发现主题股票。三次探测包含两次索引和一次 PDF，没有探测新能源，不报告其真实采集成功。

[财联社公开电报页面](https://www.cls.cn/telegraph)经过最多三次有界读取评估，页面响应未携带可归档电报列表；旧 `nodeapi/updateTelegraphList` 路径返回 404。此次不接入该源，也不使用搜索摘要替代原文，不继续猜接口或重试。

## 当前实现边界

- 来源类型是**公司公告**，不是完整行业新闻、电报或实时资讯流。
- 仅允许固定映射：`ai → 人工智能`、`robotics → 机器人`、`new_energy → 新能源`。每个选定主题仅取第一页、5 条，最多 3 页；响应和 API 明确标记 `coverage=limited_recent_sample`，不声称完整覆盖。
- 提供商的搜索可能匹配正文，但本轮只读取标题。仅标题含明确关键词的条目进入研究列表；不从关键词推断公司受益或可交易。
- 原始索引 JSON 全部归档；符合附件大小限制的命中条目同步归档官方原始 PDF。供应商声明超限的条目列入 `excluded_items`，不进入研究 `items`。`content_kind=announcement_title`，`content` 只有原站公告标题，**不是 PDF 全文、摘要或提取正文**。PDF 不执行、不渲染、不送入模型。
- 股票身份只来自官方 `secCode/secName/pageColumn`，并经过现有沪深 A 股范围校验。只证明公告发行人身份，不证明其属于某主题、受益于事件或已通过每日交易规则。研究若要关联证券，还必须核对独立归档主题成员。
- `announcementTime` 按供应商毫秒时间戳转 UTC，明确 `publication_time_precision=provider_timestamp_unverified`。实际响应含日期边界时间，不把它解释为认证的盘中发布时间。缺失时间留空、未来时间标记 `future`；两者均不能作为新鲜证据。

## 时间、证据与查询契约

`ingest_news(connection, evidence_dir, topics=('ai','robotics','new_energy'), timeout=45)` 使用自身 UTC 接收时钟，没有回填知识时间参数。每次归档保存请求参数、逐页接收时间、HTTP 客户端接收的响应内容字节、JSON/PDF SHA-256，以及绑定上述内容和规范化结果的 manifest。字节不包括 TLS 网络帧。

PostgreSQL 的 `qd_ashare_news_receipts` 和 `qd_ashare_news_items` 只追加；数据库触发器拒绝 UPDATE、DELETE、TRUNCATE。相同文章再次观测和内容修订都留存；研究列表仅返回每篇文章在查询时点已知的最新版本，不删除版本；较早时点查询仍能看到当时版本。选定最新版本并过滤主题后，先按有效发布时间降序排列，再列未来时间条目，最后列时间缺失条目；同组同发布时间按接收时间降序、版本 ID 稳定排序，最后才应用条数限制。未来时间标记不因排序而改变，也不能供研究使用。

`NewsStore(connection).list_items(topics, known_at, limit=100)` 是只读研究入口，要求带时区且不晚于现在的 `known_at`。只能看到该时点已经收到的归档；即使公告日期更早，首次归档之前也返回未观测。查询最多核验最近 20 个已知回执，超出范围标记 `truncated`。对选中回执，先重新校验整个 manifest、全部原始文件、重新规范化结果和全部数据库条目，再过滤主题和限制返回条数。文件损坏或数据库不一致时整次失败，不返回部分可信结果。

条目字段包括 `id`（回执与文章组合的唯一版本 ID）、`article_id`、`title`、`content`、`content_kind`、`published_at`、`received_at`、`known_at`、`timestamp_status`、`source`、`source_url`、`source_hash`、`pdf_hash`、`content_hash`、`topics`、`securities`、`stock_symbols`。`source_hash` 是该条所在原始索引 JSON 的 SHA-256，`pdf_hash` 是原始 PDF 的 SHA-256；回执自身的 `source_hash` 则绑定 manifest。条目 ID 可被研究候选引用以追溯确切版本。

## 请求与故障限制

只访问固定 HTTPS 索引及严格验证的 `static.cninfo.com.cn/finalpage/日期/数字ID.PDF` 路径，不接受用户 URL、不跟随重定向、不自动重试、不读取环境代理或隐式网络凭据。最多 18 个 HTTP 请求（3 个索引与至多 15 个去重 PDF）；单索引 256 KiB、单 PDF 2 MiB、总响应 16 MiB；子进程强制整个采集时限，默认 45 秒、最高 120 秒。

索引缺页、异常字段、重复冲突身份、应收却缺失的 PDF、非 PDF 响应、超时或实际下载超限均不发布回执。对 `adjunctSize`，以供应商 KB 的保守假设按 1024 字节换算，声明超过 2 MiB 时不发起该 PDF 请求；这不是对供应商单位或真实字节数的认证。清单及回执保存排除条目的 ID、标题、主题、来源 URL、声明大小、换算单位、原因与 `original_pdf_archived=false`。缺失或偏小的声明不会放宽实际下载字节限制。零关键词命中可发布真实零条回执，但不表示产生了股票推荐。失败保留旧归档，旧公告不冒充新鲜资讯。不调用模型、不修改自选、不批准策略、不下单；实盘与 AI 自动晋级继续禁止。

## 首次部署失败的有界诊断

首次生产任务没有发布回执。随后使用同一镜像的一次有界诊断显示三个索引均 HTTP 200，八个 PDF 完整取得，读取吉林吉电新能源审计报告 `1225676397` 时超过单 PDF 2 MiB 上限而失败；索引已声明其 `adjunctSize=18649`，另一资产评估附件 `1225676398` 声明为 23517。正常小附件字节数与声明值之比约为 KB 量级；未取得官方单位契约，因此大小仅用于保守排除，实际字节上限继续独立执行。

诊断第一次启动曾因新诊断目录 UID 权限错误中止，保留失败记录；修正并无网络验证目录权限后才进行了获准的一次有界抓取。修复后使用已保存的原始响应作无网络回放，得到八条完整 PDF 公告及两条显式排除。回放没有写生产数据库，其合成回放时钟不能当历史接收时间。真实生产再次采集仍须独立验收。底层已知失败现在通过严格 `SAFE_NEWS_ERRORS` 白名单输出机器错误码，未知异常、路径或供应商文本继续脱敏。
